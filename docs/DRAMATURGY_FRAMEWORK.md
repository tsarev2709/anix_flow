# Фреймворк драматургического проектирования · 0.2

## Область и результаты

Первая реализация предназначена для коротких аудиовизуальных произведений с определённой коммуникативной задачей. Она не претендует на исчерпывающую классификацию искусства.

1. **ТЗ:** задача, аудитория, изменение, смысл, действие, противоречие, зрительское обещание, композиционный принцип, обоснование, свидетельства, предположения, вопросы.
2. **Драматургический результат:** несколько вариантов с самостоятельными принципами рассказа, логлайнами, обоснованиями, компромиссами и сценами.

Основа — типизированные сущности и отношения. ТЗ не является сценарием; намерение автора не является измеренной интерпретацией зрителя.

## Смысловой паспорт

| ID | Блок | Реализация |
| --- | --- | --- |
| P1 | Аудитория | Кто, что знает, где и зачем смотрит |
| P2 | Исходное состояние | Профиль с указанием гипотез |
| P3 | Целевое изменение | Описание и несколько выбранных сфер воздействия |
| P4 | Утверждения | Claim с устойчивым ID |
| P5 | Действие | Наблюдаемое поведение в контексте |
| P6 | Основания | Source, цитата, статус знания |
| P7 | Ограничения | Численные рамки, обязательные и запрещённые фразы |
| P8 | Успех | Отдельный способ проверки |

Сферы P3: знания, убеждения, ценности, переживание, намерение, действие. Это различные предметы оценки, а не доказанный шестимерный евклидов базис. Несколько сфер могут меняться совместно.

Claim.origin: `explicit`, `inferred`, `unknown`. Два последних требуют ручного подтверждения перед разработкой сценария. Указанная цитата должна находиться в источнике; потерянная ссылка или несовпадение блокирует разработку. Введённое вручную утверждение остаётся данными пользователя, а не автоматически подтверждённым фактом.

## Онтотон и выражение

Используется предоставленная автором модель: внутренняя структурная конфигурация произведения, связывающая представление о реальности, систему ценностей, режим переживания и организацию повествования.

| Слой | Вопрос | Поля |
| --- | --- | --- |
| Онтологический | Что возможно, что поддерживает связность мира? | world, reality |
| Аксиологический | Что значимо, какую цену имеет выбор? | values |
| Психоэмоциональный | Как и через кого переживается история? | emotion, empathy |
| Нарративно-механистический | Как раскрываются сведения и ожидания? | narrative |

Динамика хранится отдельно: стабильность, раскрытие, переход, тремор, сдвиг, полярность, схлопывание, гибридность. Это рабочий словарь; он не доказывает достаточность четырёх слоёв или взаимное исключение типов на всех уровнях. Для локальных режимов нужна сценовая модель следующей версии.

Tone of voice: формулировка, образец текста, шкалы формальности, теплоты, юмора, интенсивности 0–100. Это редакторские ориентиры, не эмпирические измерения. Они не определяют Онтотон автоматически.

Повествовательные решения разделены: порядок событий; знание зрителя относительно героя о ключевом вопросе; закрытие вопроса; ведущая перспектива. `auto` — поручение предложить решение, а не содержательная категория произведения.

## Акцент как отношение

Accent связывает объект и необязательный Claim с намерением, средством выражения, предполагаемым и нежелательным прочтением. Намерения: подчеркнуть, нормализовать, оставить неявным, раскрыть позже, оставить открытым. Сцены ссылаются на устойчивые ID смыслов и акцентов.

Отсутствие усиления не трактуется автоматически как отсутствие решения. Будничное действие без музыкального подъёма может служить нормализации. Соответствие задаче проверяет редактор; реакция зрителя остаётся гипотезой.

## Проверки

Бюджет слов: `floor((duration − silent_seconds) × wpm / 60)`.

Резерв без речи включает паузы и немые планы. В каждой сцене проверяется `word_count × 60 / wpm ≤ scene.duration`. Сумма сцен сравнивается с целевой длительностью и допуском. Фактическая длительность требует записи голоса.

Слова считаются по Unicode-буквам и цифрам; дефисное слово — одна единица. Предложения отделяются `. ! ? …`. Сокращения и десятичные дроби требуют просмотра. Это счётная конвенция. Ограничение применяется к речи, не к режиссёрскому описанию.

Обязательные фразы ищутся в речи; запрещённые — в речи и изображении. Поиск буквальный без учёта регистра; перефразировки проверяются вручную. Покрытие ID проверяет граф ссылок, но не доказывает смысловое соответствие. Художественное качество, тон и эффект требуют редакторской и зрительской проверки.

LLM получает JSON Schema и паспорт. При неверной структуре — одна попытка исправления. После генерации вариантов предусмотрена ещё одна итерация исправления измеримых нарушений с сохранением смысла. Оставшиеся нарушения отображаются и блокируют выбор до правки и пересчёта.

## Версии

- API вычисляет SHA-256 нормализованного ProjectInput. Изменение входного поля делает прежний отпечаток недействительным.
- Интерфейс сохраняет точные снимки входа и ТЗ рядом со сценарием. Для новых вариантов требуется согласование текущего ТЗ.
- Редактура сцены делает отчёт устаревшим. До пересчёта он не разрешает выбрать вариант.
- `llm` и `template` — разные режимы происхождения. Недоступная модель не подменяется шаблоном.
- Архив ограничен 20 заменёнными результатами. JSON сохраняет его вместе с проектом.
