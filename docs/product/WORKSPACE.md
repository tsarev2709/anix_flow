# Страница работы над проектом

Цель: за 1–2 минуты понять, что происходит, какая версия принята, где блокер и что делать дальше.

## Информационная структура

| Область | Содержимое | Главное действие |
|---|---|---|
| Шапка | Проект, клиент, роль, локальный/командный режим, сохранение/конфликт | Сохранить, экспортировать, открыть историю |
| Обзор | Ближайший шаг, актуальность ТЗ/сценария, выбор варианта | Продолжить работу |
| Маршрут | Все эпики производства; состояния planned/draft/ready/approved/stale/blocked | Перейти в реализованный редактор |
| Исключения | Ошибки, открытые правки, просроченные согласования, неизвестные jobs | Открыть конкретный объект |
| Сцены | Стабильный ID, номер, смысл, длительность, выбранные планы/клипы | Работать со сценой |
| Рабочая область | Редактор/просмотр по типу объекта | Редактировать и сравнить версии |
| Инспектор | Входная версия, зависимости, источники, проверки | Понять причину решения и последствия правки |
| Позднее: таймлайн | Видео, звук, переходы, цветовые версии, timecode-комментарии | Собрать и экспортировать монтаж |

## CJM страницы

| Момент | Задача пользователя | Барьер | Поддержка |
|---|---|---|---|
| Открытие | Восстановить контекст | Неясно, кто что менял | Последняя ревизия, последние события и следующий шаг |
| Выбор работы | Найти важное | Слишком много статусов | Очередь исключений и фильтр моей роли |
| Работа со сценой | Увидеть связанные решения | Тексты/медиа разбросаны | Одна сцена связывает смысл → планы → ассеты → видео → цвет |
| Правка | Понять, что затрону | Старое согласование выглядит действующим | Diff, stale-маркеры и список зависимостей |
| Передача | Передать конкретный результат | «Последняя версия» неоднозначна | Ссылка на неизменяемую ревизию и review request |
| Возвращение после сбоя | Продолжить без потери | Несохранённый черновик или конфликт | Состояние сохранения, локальный черновик и копия/сравнение |

## USM и срезы

Backbone: открыть → понять состояние → выбрать действие → работать с объектом → проверить → согласовать → передать.

| Срез | Истории | Что входит |
|---|---|---|
| Сейчас | E14-US01 | Обзор, маршрут всех этапов, актуальность, следующий шаг, выбор существующего сценария |
| Ближайший | E14-US02 + E03-US02 | Полная карточка сцены и редактор порядка; роли и уведомления не имитируются |
| Командный | E14-US03 + E15-US03 | Исключения, задания, роли, клиентский просмотр и вход |
| Медиа | E10–E13 | Галереи, player, proxy, timecode и timeline |

## Правила UX

- Будущие этапы имеют метку «Запланировано» и не открывают пустой экран с обещанием работающей генерации.
- Источник, версия и статус согласования видны отдельно. Наличие данных не равно готовности.
- Неизвестное / не применимо / не измерено / другое — разные состояния.
- Потеря связи со смыслом, устаревший результат и отсутствие медиа — разные причины блокировки.
- Автосохранение черновика в браузере отличается от сохранённой копии API. Конфликт показывает ожидаемую и текущую ревизии.
- Переход между проектами не применяет поздний ответ запроса к другому проекту.
- На мобильном: обзор и review; сложный timeline проектируется для большого экрана. Таблицы могут прокручиваться внутри, не растягивая страницу.

## Сценарии проверки

Пустой проект; готовое ТЗ без сценария; изменение брифа после принятого сценария; удаление используемого источника; несохранённый черновик; два окна сохраняют разные изменения; API недоступен; проект имеет только часть сцен; рендер закончен по старой версии; история восстановлена как новая ветвь.
