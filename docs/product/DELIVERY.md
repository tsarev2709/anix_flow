## Ритм недели

Понедельник: выбрать конкретные истории и критерий демонстрации; отметить зависимости. В ходе работы: не менять исходную задачу без обновления критериев; фиксировать код и проверку в issue. Пятница: показать результат на брифе Anix, обновить статус и риски. Воскресенье: закрыть только принятые истории, остаток перепланировать.

Это рабочий регламент, без созданных напоминаний и календарных событий.

## Definition of Ready

Названы роль, проблема, вход/выход, критерий приёмки, необходимые сущности/версии и зависимость. Для интеграции известны API, формат ошибок и стоимость. Для медиа есть тестовый ассет и бюджет пробного запуска.

## Definition of Done

Поведение реализовано; meaningful tests и сборка пройдены; данные не теряются; миграция/обратная совместимость описаны; документация актуальна; есть ссылка на PR; при существенной визуальной правке проведена визуальная проверка. Принятие истории отделено от успешного CI.

## Основные риски

Качество реальной локальной LLM и доступная память; Windows-запуск; контекст и длинные документы; оценка художественного результата; возможности/стоимость медиа API; права на исходные ассеты; объём команды; долговечность ссылок и восстановление хранилища. Проверять маленькими вертикальными срезами: один бриф → одно ТЗ → один сценарий → одна сцена → два плана → два клипа → короткий мастер.
